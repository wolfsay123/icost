# 智记记账逻辑优化路线

更新日期：2026-09-05

## 北极星

在不丢失 v5 用户数据、不降低现有功能且不引入许可证污染的前提下，让每一笔金额变化都可精确计算、可追溯、可撤销，并让自动记账和坚果云同步在异常情况下默认保护用户数据。

参考来源、固定提交和许可证边界见 `docs/OPEN_SOURCE_REFERENCE.md`。

## 当前判断

智记不需要换技术栈，也不需要整体移植其他 App。继续使用 Capacitor + JavaScript 领域模块 + Android 原生系统桥接，逐步强化以下薄弱点：

| 领域 | 当前 v5 | 目标状态 | 优先级 |
| --- | --- | --- | --- |
| 金额 | `Number` 保存元，操作后两位舍入 | 整数最小单位，币种精度显式，余额链路无浮点 | P0 |
| 转账 | 单记录保存目标账户，余额投影已有 | 保留单记录，补跨币种双端金额和完整不变量 | P0 |
| 周期账 | 用户手动执行后推进 `nextDate` | 稳定期次 ID、幂等生成、结束/跳过/提前执行 | P0 |
| 自动候选 | 包名限制、脱敏、指纹、队列和确认已具备 | 字段级置信度、解析器版本、跨渠道证据合并 | P0 |
| 恢复 | AES-GCM、schema 规范化、修订冲突 | 恢复前完整引用校验、条件上传、多快照可回退 | P0 |
| 预算 | 月预算和单分类预算 | 自定义周期与账户/分类/成员/商家/标签范围 | P1 |
| 拆分/关联 | 单一关联 ID，界面和约束不完整 | 父子项金额守恒、关系组查看和整体撤销 | P1 |
| 导入 | JSON、Excel XML 基础导入 | 预览、映射、重复检测、失败行和批次回滚 | P1 |

## 数据模型 v6 方案

### 金额对象

持久化字段统一使用以下语义：

```text
amountMinor: 整数，交易币种的最小单位
currencyCode: ISO 4217 代码或智记登记的自定义代码
fractionDigits: 该币种小数位，默认从币种表读取
baseAmountMinor: 可选，锁定汇率后折算到本位币的最小单位
exchangeRate: 十进制字符串，不使用二进制浮点参与持久化计算
```

兼容策略：

1. v5 -> v6 迁移读取旧 `amount`，按交易币种精度执行一次明确的四舍五入。
2. 迁移前后分别计算每个账户余额、月收支、净资产、退款余额、结算余额和信用卡应还；任一不一致则停止迁移并保留原数据。
3. v6 备份继续保留 `version`，导出展示时才把最小单位格式化为元。
4. 回滚到 v5 前必须先导出 v5 兼容备份；v5 不允许直接读取仅含 `amountMinor` 的高版本数据。

### 交易关系

交易仍使用一个规范记录，避免引入两条互为镜像且可能失配的记录：

```text
transaction.id
transaction.type
transaction.accountId
transaction.targetAccountId
transaction.amountMinor
transaction.targetAmountMinor
transaction.relationshipId
transaction.generatedBy
transaction.deletedAt
```

领域层必须提供统一的 `accountImpacts(transaction)`，余额、净资产、报表、回收站和小组件只能消费该结果，页面不得自行判断正负号。

核心不变量：

- 普通支出/收入只影响一个账户。
- 转账同时影响两个不同账户；同币种时两端金额相等，跨币种时两端金额与锁定汇率可互相复核。
- 应收应付在未结算时只影响债权债务，不计现金账户；结算交易与分配关系必须可逆。
- 报销本金不进入普通收支，差额独立记录；撤销到账时恢复来源状态。
- 退款累计不得超过原交易金额，删除/恢复退款后净额立即回算。
- 存钱计划使用真实转账，不改变总净资产。

### 生成来源与幂等键

周期账、分期、报销、结算、存钱计划和自动候选统一保存：

```text
generatedBy.kind
generatedBy.sourceId
generatedBy.occurrenceId
generatedBy.parserVersion
```

`kind + sourceId + occurrenceId` 在有效交易中必须唯一。软删除后再次执行默认恢复或提示原记录，不能无提示地生成第二笔。

## 自动候选 v2

管线固定为：

1. **采集**：只接受用户授权的包名、通知、短信或无障碍事件。
2. **过滤**：支付结果页/动账通知白名单；付款操作页、验证码和营销信息黑名单。
3. **解析**：输出候选 DTO，不写交易表。
4. **去重**：先稳定交易号，再精确指纹，再跨渠道语义匹配。
5. **合并**：每个字段保留值、来源、置信度和提取规则版本。
6. **确认**：用户可修改账户、分类、金额、日期和备注；确认后才调用统一交易校验。
7. **审计**：保存候选 ID；忽略、失败和确认都进入有期限的处理历史。

最低候选字段：

```text
id, sourcePackage, sourceChannel, capturedAt, sanitizedText,
type, amountMinor, currencyCode, merchant, accountHint,
platformTransactionId, fingerprint, confidenceByField, parserVersion
```

安全约束：

- 不申请或使用 Root/Xposed/LSPatch 能力。
- 无障碍服务不执行点击、输入、确认支付或跨 App 自动操作。
- 同金额、同商户、相近时间但没有交易号时，只显示“可能重复”，不静默丢弃。
- 日志不得保留完整手机号、银行卡号、订单号或未经脱敏的通知正文。

## 周期账与分期

计划与生成实例分开保存：

```text
schedule: 规则、开始/结束、下一次执行、状态
occurrence: scheduleId、计划日期、执行状态、transactionId、executedAt
```

执行规则：

- 每次唤醒可补齐过去所有到期实例，但设置单次上限并在 UI 告知剩余数量。
- “创建交易”和“标记实例完成”必须同一次本地提交完成。
- 编辑规则默认只影响未来实例，历史交易保持不变。
- 支持暂停、继续、跳过、提前执行和结束日期/次数。
- 31 日月账在短月落到月末，下一期仍以原锚点 31 日计算，不能永久漂移到 28 日。
- 分期尾期使用“总额 - 已生成各期合计”，保证金额严格守恒。

## 预算范围

预算对象增加：

```text
period: monthly | weekly | yearly | custom
periodLength: 正整数
scope.accountIds/categoryIds/memberIds/merchantIds/tagIds/transactionTypes
scope.excludedCategoryIds
scope.includeRefunds/includeReimbursements/includeDebt/includeBalanceAdjustments
rollover: none | positive | all
```

预算统计必须从统一净额函数获取交易贡献值。默认规则保持当前体验：普通支出计预算、收入/转账/借贷/余额调整不计、退款冲减原支出、待报销支出是否计入由预算设置明确控制。

## 坚果云同步强化

保持“一份加密完整备份”模型，增加写入前置条件和恢复保护：

1. 下载远端信封，记录 `ETag`、修改时间、设备 ID 和数据修订号。
2. 自动上传只在本地有改动且远端仍是上次读取版本时执行。
3. 支持时使用 `If-Match: <etag>`；返回 412 时进入冲突状态，不重试覆盖。
4. 不支持条件写入时沿用现有设备修订号和时间戳冲突提示。
5. 上传后重新下载并完成 AES-GCM 解密、摘要和 schema 校验，再标记同步成功。
6. 新快照验证成功后才清理超量旧备份；至少保留一个可恢复旧版本。

真实坚果云是否支持所需 `ETag`/条件写入必须用用户测试路径验证，未验证前不能宣称完成。

## 实施批次

### 批次 1：财务精度与恢复闸门

状态：已于 2026-09-05 在 0.9.0 完成；真实坚果云和红米 K80 覆盖升级仍按验收边界待验证。

- 引入金额最小单位帮助函数和 v5/v6 双格式迁移测试。
- 将领域计算迁移到整数，页面仍显示现有两位金额。
- 增加备份引用完整性验证和“未知高版本拒绝覆盖”。

验收：固定账本迁移前后逐账户余额、净资产、月收支、信用应还、退款和结算结果完全一致；旧备份可恢复；损坏备份不改本地数据。

### 批次 2：生成任务幂等

- 周期账和分期增加 occurrence 记录、稳定幂等键和月末锚点。
- 补暂停、跳过、提前执行、结束条件和删除策略。

验收：同一任务重复执行、重启后执行和设备时间回拨均不重复入账；分期总和等于原始总额。

### 批次 3：自动候选证据链

- 候选增加字段级来源、解析器版本和稳定交易号。
- 去重分为确定重复与疑似重复；疑似项交给用户选择。
- 账户/商户/分类映射只形成建议，不覆盖用户确认值。

验收：微信/支付宝支付、收款、退款、转账、验证码、付款操作页和跨渠道重复样例全部有明确 PASS/FAIL；任何候选在确认前交易数不变。

### 批次 4：预算范围与拆分

- 扩展预算周期和筛选范围。
- 完成拆分父子项、关系组查看、批量编辑和整体撤销。

验收：固定数据集可手算复核每类预算；拆分编辑、删除、恢复始终金额守恒。

### 批次 5：坚果云条件同步

- 增加 ETag/条件上传、上传后下载验真和历史快照。
- 使用独立测试路径完成两台安装冲突演练。

验收：并发修改不会静默覆盖；错误密钥、断网、412、损坏远端文件和高版本备份都保留本地数据。

## 每批交付规则

- 先补领域测试，再改页面和 Android 桥接。
- 每批单独升级版本、更新 `docs/CHANGELOG.md`、构建验签 APK，并记录旧备份兼容性。
- 前端改动继续在 320x720、393x873、412x915、453x873 和 150% 文字大小下截图验收。
- Android 系统能力和坚果云只能以真机/真实 WebDAV 证据完成，浏览器模拟通过不能替代。
- 每批独立提交，回滚使用 `git revert <commit-sha>`；涉及 v6 数据时回滚前必须先导出兼容备份。
